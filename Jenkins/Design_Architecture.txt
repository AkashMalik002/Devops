Jenkins Architecture Notes
----------------------------------------------
1. What is Jenkins?
=> Jenkins is an open-source automation server for CI/CD. It is written in Java and runs as a web app (default port 8080). Its functionality comes from plugins.
----------------------------------------------

4. Controller–Agent Communication
SSH (outbound): the controller connects to the agent. Common for Linux.
Inbound (JNLP/WebSocket): the agent connects to the controller. Useful behind firewalls and for Windows.
Cloud/Dynamic agents: Docker, Kubernetes, or EC2 plugins spin up agents on demand and destroy them after the build.
------------------------------------------------------------------------
5. JENKINS_HOME Structure
JENKINS_HOME/
├── config.xml          # Global config
├── jobs/               # Job configs and build history
├── nodes/              # Agent definitions
├── plugins/            # Installed plugins
├── secrets/            # Encryption keys
├── users/              # User data
└── workspace/          # Build workspaces (on controller)

Back up this directory to protect your Jenkins setup.

------------------------------------------------------------------------
6. Pipeline Architecture
Jenkinsfile: pipeline-as-code stored in the repo.
Declarative: structured syntax (pipeline { agent, stages, steps }).
Scripted: Groovy-based and more flexible.
Flow: Checkout → Build → Test → Package → Deploy.
Shared Libraries: reusable Groovy code shared across pipelines.
